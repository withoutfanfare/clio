# Clio Operational Roadmap

This is the canonical register for unfinished deployment, installation and
infrastructure work. The [deployment runbook](deployment.md) explains how to
operate the current system; this file records what still needs to change.

## Keeping the roadmap current

- Review it after every Atlas deployment and on the first working day of each
  month.
- Use only `Planned`, `In progress`, `Blocked` or `Done` as statuses. A blocked
  item must state the condition that will unblock it.
- When work starts, add its issue or pull request link to the status cell and
  keep the roadmap ID in that issue or pull request.
- Mark an item `Done` only when its "Finished when" evidence has been checked.
  Move completed rows to a `Completed` section rather than deleting them.
- Update the corresponding importance-5 Clio project memory after changing
  this file. Git remains the source of truth if the two disagree.

Priority 1 is the next resilience or usability work. Priority 2 becomes useful
as releases, hosts or operational reliance increase.

Atlas retained a verified online backup (`20261115T150115Z-88709ad…`). The deploy used `CLIO_ALLOW_LIVE_MIGRATION=1` and `CLIO_KEEP_MCP_SESSIONS=1`. Compatibility review for the live migration: `018` only rewrites `attention_items.namespace` values from bare project names to their `project:` form (53 rows) and changes no schema, so the older MCP binary reads and writes the table as before. The 13 MCP sessions connected at the time stay on older code until their clients reconnect; an old session can still file a follow-up under a bare name, and treats a revival proposal in the review queue as an ordinary item, so restart them.

Checks after activation: `atlas-release.sh status` reports both stable links in the new release; migration `018` is recorded and no follow-up remains under a bare namespace; `clio export --output -` on Atlas leaves the total access count unchanged (189,081 before and after); twelve prompt briefs run on Atlas with fused retrieval on took p50 337 ms and p95 371 ms; a plain sentence given to `clio recall --query` from each Mac returns results (254 matches) where the previous release returned none; both daemons report healthy; and both desktop apps are signed builds of this commit (the MacBook Pro's was launched and quit cleanly; neither window was inspected).

The desktop app's UI dependency `@stuntrocket/ui` resolves to a private registry on `localhost:4873` that was not running (CLIO-REL-002). The stored `ui-0.6.0.tgz`, whose checksum matches the lockfile, was added to npm's cache on each Mac (`npm cache add`) so `npm ci` needed no registry.

The hook package on both Macs is at `~/.claude` commit `f34690d` (62 tests): briefs are fetched with `--no-record` and only the injected ids are acknowledged, and the prompt hook sends 1,000 characters of the prompt. A live check on the MacBook Pro injected 20 items and Atlas recorded exactly those 20 under `resume:ack`.

The agent session ran every deploy and install command in this release.
